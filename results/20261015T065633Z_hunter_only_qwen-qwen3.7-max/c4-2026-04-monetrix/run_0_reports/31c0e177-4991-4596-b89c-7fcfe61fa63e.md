### Missing domain separation in bridge action encoding enables cross-context replay

**Severity (estimated):** Medium  
**Confidence:** 0%  
**Affected:** sendBridgeToL1, _sendRaw, bridgeYieldFromL1

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. Operator calls bridgeYieldFromL1(amount) on Chain A, producing action bytes via sendBridgeToL1.
2. The action payload contains only: ACTION_VERSION, ACTION_SEND_ASSET, USDC_SYSTEM_ADDRESS, address(0), SPOT_DEX, token index, and l1Amount.
3. No chain ID, contract address, or vault identifier is included in the encoded action.
4. If the HyperCore CORE_WRITER processes actions across multiple chains or vault contexts, an attacker who observes the action on Chain A can submit the identical action bytes on Chain B.
5. The action would be processed on Chain B, potentially moving USDC that was not intended to be bridged from that context.

2. In cross-chain bridge conventions, address(0) typically signals a burn-and-mint pattern.
3. If the L1 side interprets address(0) literally as a transfer recipient rather than a burn signal, USDC is sent to the zer
