### Attack chain: Unsigned EIP-712 Fields + Inconsistent DelegateCall Dispatch Bypass

**Severity (estimated):** High  
**Confidence:** 70%  
**Affected:** execute, fromPackedCalls, hash, signatureValidation, Guest._dispatchGuest, Calls._execute, Guest.fallback

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. A user signs a batch of calls intended for Guest execution. The toEIP712() function does not include the delegateCall flag in the struct hash (H0). 2. Attacker intercepts the signed payload and flips delegateCall from false to true for one of the calls. Since delegateCall is unsigned, the signature remains valid. 3. The modified payload is submitted to execute(). Guest._dispatchGuest() checks the delegateCall flag and reverts with DelegateCallNotAllowed(i) (H16). 4. However, the execution falls through to the fallback dispatch path (Calls._execute), which DOES allow delegateCall and forwards to IDelegatedExtension.handleSequenceDelegateCall. 5. The delegatecall executes in the wallet's context, potentially modifying storage or draining funds. H0 enables the flag mutation; H16 provides the bypass path. Neither alone achieves the exploit: without H0 the flag can't be mutated, and without H16 the Guest revert would block execution entirely.

Chain steps:
  1. toEIP712 / hash: Attacker flips delegateCall flag from false to true in signed payload (field not in struct hash) → Modified payload passes signature validation since delegateCall is unsigned
  2. Guest._dispatchGuest: Execute modified payload through Guest dispatch → Guest reverts with DelegateCallNotAllowed, but execution falls through to fallback path
  3. Calls._execute / Guest.fallback: Fallback dispatch processes the delegateCall-enabled call → DelegateCall executes attacker-controlled code in wallet proxy context, enabling storage manipulation or fund extraction

Root cause: toEIP712 omits delegateCall from signed hash, and Guest/Calls handle delegateCall inconsistently, allowing bypass via fallback dispatch path
