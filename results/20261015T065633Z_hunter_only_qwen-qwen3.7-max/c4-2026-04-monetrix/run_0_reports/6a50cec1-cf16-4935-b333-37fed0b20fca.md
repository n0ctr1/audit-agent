### Attack chain: Limit Order Replay → Unvalidated Action Execution → Cross-Context Bridge Replay

**Severity (estimated):** High  
**Confidence:** 70%  
**Affected:** _sendLimitOrder, emergencyBridgePrincipalFromL1, _sendL1Bridge, _sendRaw, sendBridgeToL1, bridgeYieldFromL1

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. A user signs a limit order via _sendLimitOrder to buy asset X at price P. The signed action bytes contain no nonce field (H1). 2. After the order is legitimately executed once, an attacker re-submits the identical signed action bytes. Because there is no nonce, the contract accepts the replay. 3. The replayed action flows through _sendRaw (H7), which calls ICoreWriter.sendRawAction but does not check the return value. Even if the action fails or produces an unexpected result, the transaction continues without revert. 4. H12: If the replayed action's payload can be reinterpreted as a bridge action (due to missing domain separation in action encoding — the payload contains only ACTION_VERSION, ACTION_SEND_ASSET, token index, and amount with no context identifier), the attacker can cause the system to execute a bridge transfer that was never authorized by the original signer. This allows unauthorized extraction of USDC from the vault to an attacker-controlled L1 address.

Chain steps:
  1. _sendLimitOrder: Attacker re-submits a previously executed signed limit order (no nonce check) → Contract accepts the replayed action as valid
  2. _sendRaw / ICoreWriter.sendRawAction: Replayed action dispatched via _sendRaw; return value not validated → Even if the action produces an error or unexpected state, execution continues
  3. sendBridgeToL1 (action encoding): Missing domain separation allows the replayed limit order bytes to be interpreted as a bridge action → Unauthorized bridge transfer executed, extracting USDC from the vault to attacker's L1 address

Root cause: Signed limit orders lack a nonce, allowing unlimited replay; the underlying _sendRaw does not validate ICoreWriter return values, and bridge actions lack domain separation, enabling replayed actions to be reinterpreted across contexts.
