### Nonce field defaults to 0 when nonceSize flag is 0 — potential unsigned/fallback sentinel in packed payload

**Severity (estimated):** High  
**Confidence:** 0%  
**Affected:** fromPackedCalls, signatureValidation, _consumeNonce, execute

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. In fromPackedCalls, the 3-bit nonceSize field is extracted from globalFlag: nonceSize = (globalFlag >> 1) & 0x07. 2. When nonceSize == 0, the nonce is never read from the packed bytes and _decoded.nonce remains at its Solidity default of 0. 3. If the toEIP712 struct hash does not explicitly include the nonce (or encodes it in a way that omits it when zero), the nonce is an unsigned field — the attacker can modify the packed payload bytes to set any nonceSize/nonce value without invalidating the signature. 4. Even if nonce IS in the hash, the implicit default of 0 acts as a fallback sentinel: any signer creating a standard-format signature with nonceSize=0 is implicitly signing nonce=0, which may not be the signer's intent. 5. _consumeNonce checks currentNonce == _nonce and increments, so the first call in any space (currentNonce=0) will succeed with the default nonce=0 without the signer having explicitly encoded a nonce in the payload.
