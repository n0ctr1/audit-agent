### Attack chain: Unsigned EIP-712 Fields + Nonce Default Enable Persistent Signature Replay with DelegateCall Hijack

**Severity (estimated):** Critical  
**Confidence:** 70%  
**Affected:** execute, fromPackedCalls, hash, signatureValidation, _consumeNonce

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. A legitimate user signs a transaction payload via the wallet's EIP-712 signature scheme. The toEIP712() function omits fields like delegateCall, onlyFallback, behaviorOnError, and gasLimit from the struct hash (H0). 2. The attacker intercepts this signed payload and modifies it: sets nonceSize=0 in the globalFlag (3-bit field), which causes fromPackedCalls to never read a nonce from the packed bytes, leaving _decoded.nonce at its Solidity default of 0 (H6). 3. The attacker also flips the delegateCall flag from false to true in the unsigned portion of the payload. Since neither the nonce nor delegateCall are covered by the signature hash, the modified payload still passes signature validation. 4. The attacker submits this payload to execute(). Because nonce is always 0, the same modified payload can be replayed indefinitely across multiple transactions. The delegateCall=true routes execution through a delegatecall path, potentially allowing the attacker to execute arbitrary code in the wallet's context. 5. H0 alone allows field mutation but nonce tracking could prevent replay; H6 alone forces nonce=0 but signed fields can't be mutated. Together they enable persistent, replayable payload mutation.

Chain steps:
  1. fromPackedCalls: Attacker modifies intercepted signed payload: sets nonceSize=0 in globalFlag and flips delegateCall to true → Nonce defaults to 0 (never consumed from payload) and delegateCall is mutated, both outside the signed hash
  2. signatureValidation: Submit modified payload for validation → Signature verification passes because neither nonce nor delegateCall are included in the EIP-712 struct hash
  3. execute: Execute the mutated payload with delegateCall=true and nonce=0 → DelegateCall executes attacker code in wallet context; nonce=0 allows indefinite replay of the same payload
