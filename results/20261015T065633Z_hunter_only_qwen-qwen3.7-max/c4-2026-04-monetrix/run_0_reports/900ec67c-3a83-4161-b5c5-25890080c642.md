### distributeYield can be DoS'd by sUSDM.injectYield reverting when userShare exceeds maxYieldPerInjection cap

**Severity (estimated):** Medium  
**Confidence:** 0%  
**Affected:** distributeYield

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. Yield accumulates in YieldEscrow to a large amount (e.g., 10M USDC) over many days without distribution. 2. Governor sets maxYieldPerInjection to a conservative value (e.g., 1M USDC) as defense-in-depth. 3. The function has no mechanism to distribute in batches or cap userShare at maxYieldPerInjection.
