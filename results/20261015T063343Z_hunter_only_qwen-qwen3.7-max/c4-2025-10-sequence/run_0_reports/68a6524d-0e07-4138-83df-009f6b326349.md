### Unsigned weight field in recoverBranch allows weight inflation without invalidating signatures

**Severity (estimated):** High  
**Confidence:** 0%  
**Affected:** recoverBranch, recoverSapientSignature

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. Attacker observes a valid multi-sig transaction with a branch signature blob.
2. In the signature blob, each signer's weight is encoded in the lower nibble of the flag byte (or a subsequent byte) — this weight is NOT included in _opHash (the signed message).
3. Attacker modifies the weight nibble/byte for each signer entry in the signature blob (e.g., changing 0x01 to 0x0F for weight 15).
4. ecrecover still recovers the correct address since _opHash is unchanged.
5. The accumulated weight return value is inflated.
6. If the caller checks weight >= threshold BEFORE verifying the merkle root against the stored imageHash, the threshold check passes with forged weights.
7. Even if root is eventually checked, the inflated weight value may be used in intermediate logic or returned to callers that trust it independently.
