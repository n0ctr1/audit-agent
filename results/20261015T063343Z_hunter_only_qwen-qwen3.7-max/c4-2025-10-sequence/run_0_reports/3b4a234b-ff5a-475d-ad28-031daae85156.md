### Chained signature checkpoint=0 bypasses snapshot checkpoint enforcement

**Severity (estimated):** High  
**Confidence:** 0%  
**Affected:** recoverChained, recover

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. Attacker obtains a valid signature for a config update at checkpoint=100 (old config with higher threshold). 2. Attacker crafts a chained signature where the final (outermost) signature has checkpointSize=0 in its flag byte (bits [4..2]=000), causing readUintX to return checkpoint=0 without consuming bytes. 3. The inner signature has a valid imageHash and sufficient weight. 4. In recoverChained, the final checkpoint stored is 0. 5. The snapshot check `checkpoint <= _snapshot.checkpoint` evaluates to `0 <= N` which is always true, BUT if the snapshot imageHash was matched by any intermediate signature, `_snapshot.imageHash` is zeroed and the check is skipped entirely. 6. Even without snapshot match, if the checkpointer returns checkpoint=0, the attacker's old config signature (checkpoint=100) passes the inner weight check, and the outer signature with checkpoint=0 passes the snapshot check since 0 <= any_checkpoint. This allows using an old high-threshold config to authorize actions that the new low-threshold config shouldn't allow.
