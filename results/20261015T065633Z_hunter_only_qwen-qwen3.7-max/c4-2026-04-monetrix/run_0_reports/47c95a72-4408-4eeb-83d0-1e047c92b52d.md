### TokenMath floor-rounding accumulation in multi-asset backing calculation systematically understates surplus

**Severity (estimated):** Low  
**Confidence:** 0%  
**Affected:** TokenMath.usdcL1WeiToEvm, TokenMath.spotNotionalUsdcFromPerpPx, TokenMath.spotNotionalUsdcFromSpotPx, MonetrixAccountant._readL1Backing, PrecompileReader.spotUsdcEvm

**Why needs review:** The PoC did not succeed, but the vulnerability hypothesis is plausible based on code analysis. A human auditor must determine whether this is a real issue.

**Attack scenario:** 1. MonetrixAccountant.totalBackingSigned() aggregates backing across multiple L1 assets: perp account value, spot USDC, spot hedge tokens, and PM-supplied balances. 2. Each L1→EVM conversion via TokenMath.usdcL1WeiToEvm performs floor division by 100 (8dp→6dp), losing up to 99 wei per asset. 3. spotNotionalUsdcFromPerpPx and spotNotionalUsdcFromSpotPx also floor-divide, losing up to (divisor-1) wei per hedge token position. 4. With N tradeable assets, the cumulative rounding loss is up to N * (max_per_asset_loss). For a protocol with 10+ tradeable assets, this could be several USDC per settlement. 5. Since surplus = totalBackingSigned - usdmSupply, systematic understatement of backing means distributableSurplus is also understated. 6. Over many daily settlements, the accumulated 'lost' yield compounds — yield that was economically earned but can never be distributed. This is a cross-contract issue because TokenMath's rounding contract with Accountant's aggregation creates the emergent loss; neither contract alone has a bug.
